# Product

## Register

product

## Users

Palette is for people who have never used AI to code before, plus hackathon builders who need a clear demo quickly. The interface must make Codex feel approachable, visible, and controllable from the first moment. Users should not need to understand files, frameworks, prompts, or terminals before they feel progress.

## Product Purpose

Palette is a visual workspace for Codex that lets users paint software into existence. A user starts from a blank canvas, primes the canvas with a short interview, mixes reference swatches, then watches Codex paint a frontend in real time. The user can interrupt, steer by voice, edit directly on the canvas, and set the result into real code.

For the MVP, success means a judge can understand the product in seconds: Palette is not another AI chat box. It is a canvas where Codex becomes a live software paintbrush.

## Brand Personality

Painterly, magical, and clear.

Palette should feel like a 19th-century artist studio translated into a modern Codex workspace. The language should borrow from painting, canvas, swatches, brushstrokes, varnish, and atelier craft without becoming costume-like or hard to understand. The product should feel warm and imaginative, but still precise enough that beginners trust it.

## Anti-references

Avoid generic AI slop: default SaaS gradients, vague glass cards everywhere, predictable purple-blue AI palettes, inflated hero copy, floating orb decoration, bland generated dashboards, and any interface that looks like a first-pass AI website with no taste.

Avoid looking like a Lovable, v0, Bolt, Webflow, or Figma clone. Palette is not a generic app builder or design editor. It is a Codex-native painting surface for making real frontend code.

Avoid pure chat UX. The command surface can accept voice or text, but the main interaction should be canvas-first: interrupt, point, edit, steer, and watch the interface form.

Avoid emojis everywhere. Palette should never use emojis in UI copy, status text, demo data, logs shown in the app, or pitch-facing copy.

## Design Principles

1. Paint, do not prompt. The app should make users feel like they are guiding a brush, not filing a request into a chatbot.
2. Show formation. The frontend should appear in visible strokes and layers so the user can steer before the wrong thing is complete.
3. Keep beginners oriented. Every step should be obvious: prime the canvas, mix swatches, begin painting, guide the brush, set the paint.
4. Make interrupting natural. Voice and keyboard steering should feel like part of creation, not an error or restart.
5. Ship the demo feeling. Favor a polished, cinematic, easy-to-demo path over broad app-builder scope.

## Accessibility & Inclusion

Palette should be usable by beginners and non-coders. Keep copy plain, controls discoverable, and visual states clear. Support keyboard operation for the command capsule and core canvas actions. Respect reduced-motion preferences by replacing painting animations with staged fades. Maintain readable contrast on glass and painterly surfaces, especially for command text and action buttons.
